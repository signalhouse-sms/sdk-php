================================================================================
                    SIGNALHOUSE PHP SDK DOCUMENTATION
================================================================================

INSTALLATION
--------------------------------------------------------------------------------
  composer require signalhouse-sms/sdk


INITIALIZATION
--------------------------------------------------------------------------------
  use SignalHouse\SDK\SignalHouseSDK;

  $signalHouse = new SignalHouseSDK(
      apiKey: 'your-api-token',
      baseUrl: 'https://v2.signalhouse.io'
  );

  Required options:
    - apiKey   (string)  JWT token or service user token for authentication
    - baseUrl  (string)  API base URL

  The SDK throws an InvalidArgumentException at initialization if apiKey or
  baseUrl is missing.


PER-REQUEST TOKEN OVERRIDE
--------------------------------------------------------------------------------
  Every SDK method accepts an optional $options array with a 'token' key to
  override the default apiKey for that single request.

  Example:
    $response = $signalHouse->messages->getMessages(
        page: 1,
        limit: 10,
        options: ['token' => 'user-specific-jwt-token']
    );

  The per-request token takes precedence over the apiKey provided at
  initialization. The original apiKey remains unchanged.


CUSTOM HEADERS
--------------------------------------------------------------------------------
  Pass additional headers via the options['headers'] key:

  Example:
    $response = $signalHouse->numbers->getPhoneNumbers(
        page: 1,
        limit: 20,
        options: [
            'headers' => [
                'X-Request-Id' => 'req_abc123',
            ],
        ]
    );


IDEMPOTENT REQUESTS
--------------------------------------------------------------------------------
  Pass options['idempotencyKey'] to make a create, update or delete safe to
  retry. The SDK sends it as the Idempotency-Key header. A retry with the same
  key and the same request replays the first response, marked with the
  response header Idempotent-Replayed: true, instead of running the request
  again.

  - Use a new key (a UUID is recommended) for each new operation, and reuse
    it only to retry that exact request.
  - Keys are scoped to the authenticated user and kept for 24 hours.
  - Reusing a key for a different request returns 422; retrying while the
    first request is still running returns 409 with Retry-After.
  - The SDK never creates a key for you. GET requests ignore it, and the
    Voice service does not support it.

  Example:
    $response = $signalHouse->subgroups->createSubgroup(
        ['groupId' => 'G0000001', 'subgroupName' => 'Support'],
        ['idempotencyKey' => '6f1c2a4e-8b3d-4c5e-9f70-1a2b3c4d5e6f']
    );

AUTH  ($signalHouse->auth)
--------------------------------------------------------------------------------
  login(string $email, string $password, ?array $options)
    Login with email and password.

  resetPassword(string $userId, string $newPassword, ?array $options)
    Reset a user's password.

  getAuthHistory(?string $groupId, ?string $userId, ?int $page,
      ?int $limit, ?array $options)
    Get token login history.

  getOAuthAuthorizationUrl(string $provider, ?string $next,
      ?string $email, ?string $linkTicket, ?string $reauthTicket)
    Build (no request) the absolute URL that starts an OAuth sign-in; navigate
    a browser to it. $provider: "google", "microsoft", "apple" or "sso"
    (Enterprise SSO; requires $email, whose domain picks the identity provider).
    With $linkTicket (from createOAuthLink) it links the provider to the
    signed-in account instead; the API returns the browser to
    /Settings/Security with pendingLink (pass it to confirmOAuthLink) or
    linkError. With $reauthTicket (from createOAuthReauth) the account signs in
    again to confirm it's them ("sso" needs no $email then). Query keys, only
    when set: email, linkTicket, reauthTicket, next.

  getOAuthLinks(?array $options)
    List the caller's sign-in methods. Sends a GET to /auth/oauth/links.
    Returns { passwordKnown, links: [{ provider, email, linkedAt, lastLoginAt }] }.
    passwordKnown is false for an account created through a provider or SSO.

  createOAuthLink(string $provider, ?array $options)
    Start linking "google", "microsoft" or "apple" to the caller's account.
    Sends a POST to /auth/oauth/:provider/link (no body).
    Returns { linkTicket, expiresInSeconds }; pass linkTicket to
    getOAuthAuthorizationUrl. Requires a fresh confirmTwoFactorIdentity.
    The provider round trip returns pendingLink, which must be passed to
    confirmOAuthLink.

  createOAuthReauth(string $provider, ?array $options)
    Start signing in again with a provider linked to the caller's account
    ("microsoft", "apple" or "sso"; Google is refused with 400), to confirm it's them. Sends a
    POST to /auth/oauth/:provider/reauth (no body). Spends nothing.
    Returns { reauthTicket, reauthSecret, expiresInSeconds } (keep reauthSecret for the confirm call); pass reauthTicket to
    getOAuthAuthorizationUrl. The browser comes back to /Settings/Security
    with a single-use pendingReauth (the session that
    started it redeems it with confirmOAuthReauth) or reauthError.

  confirmOAuthReauth(string $pendingReauth, string $reauthSecret,
      ?array $options)
    Finish signing in again with a linked provider. Sends a POST to
    /auth/oauth/reauth/confirm with { pendingReauth, reauthSecret }. pendingReauth
    is the
    single-use value (valid 5 minutes) the createOAuthReauth round trip returns
    to /Settings/Security with. It counts only for the same account and
    session that started it; 400 when expired or used, 403 for another
    account or session. reauthSecret is the value the create call returned;
    a wrong or missing secret is refused (403) and uses up the re-sign-in.
    Returns: { identityConfirmed } (true when 2FA is off, so it counts as a
    confirmed identity).

  confirmOAuthLink(string $pendingLink, ?array $options)
    Finish linking a provider. Pass the single-use pendingLink that the
    createOAuthLink round trip returned to /Settings/Security; it links only
    for the account the link was started for. Sends a POST to
    /auth/oauth/links/confirm with { pendingLink }.
    Returns the caller's { passwordKnown, links: [{ provider, email, linkedAt, lastLoginAt }] }.

  deleteOAuthLink(string $provider, ?array $options)
    Unlink a provider ("google", "microsoft", "apple" or "sso") from the
    caller's account. Sends a DELETE to /auth/oauth/:provider/link.
    Refused (400) when it is the account's only sign-in method. Requires a
    fresh confirmTwoFactorIdentity. Returns the remaining { passwordKnown, links }.

  confirmTwoFactorIdentity(?string $password, ?string $code, ?string $method,
      ?bool $usingBackupCode, ?array $options)
    Confirm identity before a sensitive change (2FA changes, linking/unlinking
    providers, saving/deleting group SSO). An account without its own password
    (passwordKnown false) confirms with the code from
    sendTwoFactorIdentityCode("email") using $method "email".

  sendTwoFactorIdentityCode(string $method, ?array $options)
    Send a code by text or email for confirmTwoFactorIdentity ("sms" or
    "email"; not needed for "app"). An account without its own password
    (passwordKnown false) sends "email" here with 2FA off.

BRANDS  ($signalHouse->brands)
--------------------------------------------------------------------------------
  getBrands(array $params = [], array $options = [])
    List brands with filters. $params keys: id, subgroupId, groupId, page,
    limit, status, registrationType, currentTollFreeCarrier (bool).
    id is a brand lookup id. registrationType filters by "TEN_DLC",
    "TOLL_FREE", or "SHORT_CODE".
    currentTollFreeCarrier: with groupId or subgroupId, true returns only the
    toll-free brands a new toll-free campaign in that group can use.
    A toll-free brand's tollFree holds reviewsBusinessOnSubmit: whether the
    brand is reviewed when it's submitted and keeps its business details
    from then on. A brand reviewed on submit also holds businessStructure,
    industry, contactEmail, contactJobTitle, contactJobLevel and
    rejectionReason (why the brand was rejected, in plain English, or null)
    in its tollFree.

  createBrand(array $brandData, ?array $options)
    Create a new 10DLC brand.

  createTollFreeBrand(array $brandData, ?array $options)
    Create a new toll-free brand.
    Sends a POST to /brand/toll-free with $brandData as the body;
    registrationType is set to TOLL_FREE by the server. The toll-free fields
    go under $brandData['tollFree']: businessRegistrationType,
    legalEntityType, taxId, countryCode and supportPhone (E.164, e.g.
    "17025550100"), and optionally taxIdIssuingCountry, businessDBA and
    businessWebsite.
    A group whose toll-free brands are reviewed on submit (see
    getTollFreeRequirements) must also send these five under tollFree:
      businessStructure  CO_OPERATIVE, CORPORATION,
                         LIMITED_LIABILITY_CORPORATION,
                         NON_PROFIT_CORPORATION or PARTNERSHIP
      industry           AGRICULTURE, AUTOMOTIVE, BANKING, CONSTRUCTION,
                         CONSUMER, EDUCATION, ELECTRONICS, ENGINEERING,
                         ENERGY, FAST_MOVING_CONSUMER_GOODS, FINANCIAL,
                         FINTECH, FOOD_AND_BEVERAGE, GOVERNMENT, HEALTHCARE,
                         HOSPITALITY, INSURANCE, JEWELRY, LEGAL,
                         MANUFACTURING, MEDIA, NOT_FOR_PROFIT, OIL_AND_GAS,
                         ONLINE, PROFESSIONAL_SERVICES, RAW_MATERIALS,
                         REAL_ESTATE, RELIGION, RETAIL, TECHNOLOGY,
                         TELECOMMUNICATIONS, TRANSPORTATION or TRAVEL
      contactEmail       the contact's email address (at most 100
                         characters)
      contactJobTitle    the contact's job title (at most 100 characters)
      contactJobLevel    DIRECTOR, GM, VP, CEO, CFO, GENERAL_COUNSEL or
                         OTHER
    Its tollFree.countryCode must then be "US" or "CA" and its state a
    2-letter state or province code. Any other group gets 400 if it sends
    one of the five.
    Such a brand stays DCA_PENDING until it is reviewed, usually 1–2
    business days, then becomes DCA_ACTIVE, or DCA_REJECTED with
    tollFree.rejectionReason saying why; a rejected brand is fixed by
    creating it again with the corrections. Its business details
    (companyName, street, city, state, postalCode, country, firstName,
    lastName, tollFree's businessRegistrationType, taxId, countryCode and
    taxIdIssuingCountry, and the five above) can't be changed after it is
    submitted.
    Returns 202 with the new brand. Its brandId is a TFNB-prefixed id when
    assigned; otherwise null (poll by _id).

  getTollFreeRequirements(string $groupId, ?array $options)
    Get what a group's new toll-free brands need.
    Sends a GET to /brand/toll-free-requirements/:groupId. The caller must
    be able to view the group (403 otherwise).
    Returns 200: { groupId, reviewsBusinessOnSubmit }. When
    reviewsBusinessOnSubmit is true, the group's new toll-free brands are
    reviewed when they're submitted: createTollFreeBrand needs the five
    business details under tollFree (businessStructure, industry,
    contactEmail, contactJobTitle and contactJobLevel), a "US" or "CA"
    tollFree.countryCode and a 2-letter state or province code; the brand
    stays DCA_PENDING until it is reviewed; and its business details can't
    be changed after it is submitted.
      $signalHouse->brands->getTollFreeRequirements('G1');

  updateBrand(string $brandId, array $brandData, ?array $options)
    Update brand information.

  deleteBrand(string $brandId, ?array $options)
    Delete (soft) a brand.

  transferBrand(string $subgroupId, array $brandIds, ?array $options)
    Transfer brands to a different subgroup.

  getExternalVetting(string $brandId, ?array $options)
    Get external vetting info for a brand.

  createExternalVetting(string $brandId, ?array $options)
    Submit brand for external vetting.

  importExternalVetting(string $brandId, string $vettingProviderId, string $vettingId, ?string $vettingToken, ?array $options)
    Import an existing external vetting record (not billable).

  revetBrand(string $brandId, ?array $options)
    Resubmit brand for vetting.

  getAppealHistory(string $brandId, ?array $options)
    List identity status appeals for a brand.

  submitAppeal(string $brandId, array $appealCategories, string $explanation,
      ?string $filePath, ?array $options)
    Submit a brand identity status appeal with supporting documentation.
    Uses multipart/form-data automatically.
    $appealCategories: array of strings (VERIFY_TAX_ID, VERIFY_NON_PROFIT, VERIFY_GOVERNMENT)
    $explanation: string (max 1024 chars)
    $filePath: string path to file (supported: .jpg, .jpeg, .png, .bmp, .raw, .tiff, .pdf, .docx, .htm, .odt, .rtf, .txt, .xml)

  createWebhook(array $webhookData, ?array $options)
    Create a new webhook.

  updateWebhook(string $id, array $updateData, ?array $options)
    Update webhook configuration, including authType, apiHeaderPrefix and credentials
    (changed in place). Responses carry hasSigningSecret/hasCredentials, never secrets.

  rotateWebhookSecret(string $id, ?int $graceSeconds, ?array $options)
    Rotate the signing secret (or create a first one for an older webhook). Returns the new

================================================================================
                          MULTIPART REQUESTS
================================================================================

  The following methods use multipart/form-data automatically:

    - $signalHouse->messages->sendMMS(...)
    - $signalHouse->messages->sendGroupMessage(...)
    - $signalHouse->landings->createLanding(...)
    - $signalHouse->landings->updateLanding(...)
    - $signalHouse->brands->submitAppeal(...)

  You do not need to construct multipart form data manually. Pass parameters
  as normal arguments and the SDK builds the form data internally using
  Guzzle's multipart support.


================================================================================
                          QUERY STRING HELPERS
================================================================================

  The SDK automatically constructs query strings from method parameters.
  Any parameter with a null value is excluded, so you only need to pass
  the filters you care about.

  Example:
    // Only sends ?status=FAILED&page=1&limit=50
    $messages = $signalHouse->messages->getMessages(
        status: 'FAILED',
        groupId: null,     // excluded
        direction: null,   // excluded
        page: 1,
        limit: 50
    );


================================================================================
                             VALIDATION
================================================================================

  The SDK validates required parameters client-side before making any HTTP
  request. If a required parameter is missing, null, or an empty string,
  the SDK throws a ValidationException immediately -- no network request
  is made.

  Validation errors have:
    - Class:   SignalHouse\SDK\Exceptions\ValidationException
    - Message: "Missing required parameter: <fieldName>"
    - Code:    400


================================================================================
                           ERROR HANDLING
================================================================================

  The SDK uses a standardized response format. Errors are NOT thrown --
  they are returned as associative arrays with 'success' => false.

  Success response:
    ['success' => true, 'data' => [...], 'status' => 200]

  Error response:
    ['success' => false, 'error' => 'Error message', 'status' => 400]

  Error types summary:

    Source                    Behavior                         How to Handle
    -----------------------------------------------------------------------
    Missing required param    Throws ValidationException       try/catch
    HTTP 4xx/5xx from API     Returns ['success' => false]     Check $response['success']
    Network failure           Returns ['success' => false]     Check $response['success']

                       COMPLETE INTEGRATION EXAMPLE
================================================================================

  <?php

  require __DIR__ . '/vendor/autoload.php';

  use SignalHouse\SDK\SignalHouseSDK;
  use SignalHouse\SDK\Exceptions\ValidationException;

  // --- Laravel example ---

  // In a service provider or controller constructor:
  $signalHouse = new SignalHouseSDK(
      apiKey: env('SIGNALHOUSE_API_KEY'),
      baseUrl: 'https://v2.signalhouse.io'
  );

  // routes/api.php
  use Illuminate\Http\Request;
  use Illuminate\Support\Facades\Route;

  Route::post('/api/notify', function (Request $request) use ($signalHouse) {
      $validated = $request->validate([
          'recipientNumber' => 'required|string',
          'message'         => 'required|string',
          'senderNumber'    => 'required|string',
      ]);

      try {
          $response = $signalHouse->messages->sendSMS(
              senderPhoneNumber: $validated['senderNumber'],
              recipientPhoneNumbers: [$validated['recipientNumber']],
              messageBody: $validated['message'],
              statusCallbackUrl: config('app.url') . '/api/delivery-status'
          );

          if (!$response['success']) {
              return response()->json(
                  ['error' => $response['error']],
                  $response['status'] ?? 500
              );
          }

          return response()->json([
              'messageId' => $response['data']['messageId'],
              'status'    => $response['data']['status'],
          ]);
      } catch (ValidationException $e) {
          return response()->json(['error' => $e->getMessage()], 400);
      } catch (\Exception $e) {
          return response()->json(['error' => 'Internal server error'], 500);
      }
  });

  // Receive delivery status callbacks
  Route::post('/api/delivery-status', function (Request $request) {
      $messageId = $request->input('messageId');
      $status = $request->input('status');
      \Log::info("Message {$messageId} status: {$status}");
      return response()->json(['received' => true]);
  });

  // List phone numbers with per-request token override
  Route::get('/api/numbers', function (Request $request) use ($signalHouse) {
      $userToken = str_replace('Bearer ', '', $request->header('Authorization', ''));

      $response = $signalHouse->numbers->getPhoneNumbers(
          page: (int) $request->query('page', 1),
          limit: (int) $request->query('limit', 20),
          options: ['token' => $userToken]
      );

      if (!$response['success']) {
          return response()->json(
              ['error' => $response['error']],
              $response['status'] ?? 500
          );
      }

      return response()->json($response['data']);
  });

  // Get message analytics
  Route::get('/api/analytics', function (Request $request) use ($signalHouse) {
      $response = $signalHouse->messages->getAnalytics(
          startDate: $request->query('startDate'),
          endDate: $request->query('endDate'),
          campaignId: $request->query('campaignId')
      );

      if (!$response['success']) {
          return response()->json(
              ['error' => $response['error']],
              $response['status'] ?? 500
          );
      }

      return response()->json($response['data']);
  });


REGISTRATIONS AND REGIONAL REPORTING
--------------------------------------------------------------------------------
A registration is what a jurisdiction (or its provider) requires before a sender
may message. One model covers every jurisdiction: `region` is the jurisdiction
(US, GB, CA, AU; any case of "UK"/"GB"/"GBR"/"United Kingdom" is accepted for GB) and `type` selects the shape of `data`.
Types: TEN_DLC_BRAND, TEN_DLC_CAMPAIGN, TOLL_FREE_BRAND, TOLL_FREE_CAMPAIGN,
SHORT_CODE_BRAND, SHORT_CODE_PROGRAM, SHORT_CODE_LEASE (not available), VIRTUAL_LONG_CODE (UK) and ALPHANUMERIC_SENDER_ID (UK). Kinds: identity, program, sender. Channels: tenDLC, tollFree,
shortCode, virtualLongCode, alphanumeric.

Start with the catalog. GET /registration/catalog?region= returns {region,
jurisdiction, sendingRequiresRegistration, registeredThrough, provisioning, types:[{type, kind,
channel, provider, bundles, quantity:{min,max}, requiresParent, available}]}.
registeredThrough is "registration" (use this API), "brandsAndCampaigns" (the US:
register through the Brands and Campaigns APIs) or null (nothing to register, e.g.
Canada). An unlisted country requires registration and offers no types.
Quote and submit only a type whose `available` is true; other types answer 400.

GET /registration/quotes?region=&type=&quantity= (1-100, default 1) returns
{data:[quotes]}, one quote per capability bundle: {capabilities, quantity,
currency, setupAmount, monthlyAmount, totalSetupAmount, totalMonthlyAmount,
etaDays}. Amounts are integer microdollars; setupAmount/monthlyAmount are per
sender and the totals cover the quantity. groupId is optional and staff-only.

Submit on POST /registration (201) with region, type, subgroupId,
capabilities (one of the type's bundles) and data. Set options['idempotencyKey'] to make a
retry safe (see IDEMPOTENT REQUESTS). Worked example, UK Virtual Long Code: type "VIRTUAL_LONG_CODE",
capabilities ["SMS"] or ["SMS","VOICE"], data {quantity (1-100), useCases (1-10
strings), voice?}. The voice dossier is required exactly when capabilities
include VOICE: companyName, companyPhone, companyWebsite, companyEmail,
address {line1,line2?,city,postalCode,country}, companyDescription,
campaignName, campaignDescription, optInMethods (WEB|KEYWORD|VERBAL),
optOutKeywords (STOP and UNSUBSCRIBE), callTypes (LANDLINE|LOCAL|INTERNATIONAL),
callsPerDay (1-5), callDurationMinutes (1-10, 15, 30, 45 or 60) and termsUrl.

Worked example, UK alphanumeric sender ID: region "GB", type
"ALPHANUMERIC_SENDER_ID", capabilities ["SMS"], data {requestedSenderId (3-11
letters, digits, spaces, dots or dashes; at least one letter), trafficOrigin
(LOCAL: headquartered in the UK | INTERNATIONAL), trafficType (TRANSACTIONAL |
PROMOTIONAL), companyName, companyCountry, companyWebsite (http/https), industry,
messageExample, senderRelationship? (required when requestedSenderId differs from
companyName)}. quantity is always 1; the quote is one ["SMS"] bundle, 6000000
setup and 6000000 monthly by default. Once the registration is APPROVED,
data.phoneNumbers holds the granted sender (e.g. ["ACME"]); pass it as the sender
to send SMS to UK recipients. The server appends "\nOpt out: sihou.io/o/{code}"
to every message from it, counted in segments and in the estimate.

GET /registration accepts groupId, subgroupId, region, type, kind, status,
parentRegistrationId, phoneNumber (filter to registrations holding this phone
number), brandId and campaignId (RCS agents linked to that brand or
campaign), sortBy (createdAt (default), subgroupId, registrationId, region or
status), sortOrder (asc or desc (default)), page and limit (max 100) and returns
{data,totalCount,page,limit}.
Region and status each take one value or a list (string or array; an array is
sent as repeated keys, e.g. status=PENDING_PROVIDER&status=APPROVED).
GET /registration/:registrationId returns
{registrationId, groupId, subgroupId, region, type, kind, channel, provider,
externalId, parentRegistrationId, status, stage, capabilities, submittedAt,
approvedAt, expiresAt, review:{decision,reviewedAt,reason}, data:{...type
fields}, history:[{status,stage,actor,actorType,timestamp,reason}], createdAt,
updatedAt}. For VIRTUAL_LONG_CODE, data also carries phoneNumbers, the numbers
allocated so far. Statuses: DRAFT, SIGNAL_HOUSE_REVIEW, SIGNAL_HOUSE_APPROVED,
SIGNAL_HOUSE_REJECTED, SUBMITTING, PENDING_PROVIDER, NEEDS_INFORMATION,
PAYMENT_REQUIRED (the setup fee could not be funded; retried hourly), APPROVED,
REJECTED, CANCELLED, PENDING_DELETE, DELETED, EXPIRED, RECONCILIATION_REQUIRED.
`stage` is the provider's step inside a status. Never send from a sender whose
registration is not APPROVED.

DELETE /registration/:registrationId cancels a registration (roles api, admin,
developer, user). Allowed from SIGNAL_HOUSE_REVIEW, SIGNAL_HOUSE_APPROVED,
PENDING_PROVIDER, NEEDS_INFORMATION, PAYMENT_REQUIRED and APPROVED (409
otherwise); a type that keeps drafts (RCS_AGENT) can also be cancelled from
DRAFT and SIGNAL_HOUSE_REJECTED. Numbers already allocated stay on the account
and stop sending.

Drafts (types that keep drafts, such as RCS_AGENT):
updateRegistration(string $registrationId, array $data, array $options = [])
sends PUT /registration/:registrationId with $data as the body to edit a DRAFT
or SIGNAL_HOUSE_REJECTED registration (409 otherwise).
validateRegistration(string $registrationId, array $options = []) sends POST
/registration/:registrationId/validate and returns {valid, errors, warnings};
it writes nothing. submitRegistration(string $registrationId, array $options =
[]) sends POST /registration/:registrationId/submit and moves a draft to
SIGNAL_HOUSE_REVIEW, or to SUBMITTING for a type Signal House does not review
first (RCS_AGENT, filed with the provider at once) (400 REGISTRATION_INCOMPLETE
with the errors, 409 on a second submit). launchRegistration(string
$registrationId, array $options = []) sends POST
/registration/:registrationId/launch: an RCS agent the carrier partner holds in
testing goes to SIGNAL_HOUSE_REVIEW, whose approval files the launch (409 unless
the agent is in testing, Signal House rejected an earlier request, or every
carrier refused one; 400 REGISTRATION_INCOMPLETE with the errors).

Staff only (the admin namespace exists only when the client enables admin, and
enabling it grants no server permission):
POST /:registrationId/review {action:"APPROVE"|"REJECT",reason?}; REJECT needs reason.
POST /:registrationId/corrections {reason,data} saves the type's correctable
fields (VIRTUAL_LONG_CODE: useCases, voice?) while the provider waits; owner,
quantity, bundle and provider order are fixed.
POST /:registrationId/numbers {phoneNumber} allocates a provider-owned number
through the recovery path.
POST /:registrationId/reconcile {externalId} links the provider order that was
placed after an ambiguous submission; never place a second order to retry.
GET /:registrationId/application?format=json returns {filename,contentType,base64};
decode base64 before saving the document.

Regional reporting: GET /message, /message/analytics, /message/analytics/detail,
/message/analytics/by-subgroup, /message/analytics/by-error-code, /message/dnc and
/message/dnc/analytics accept region and regionScopes; GET
/message/analytics/filter-options accepts region only. region is US, GB or CA
(any case of "UK"/"GB"/"GBR"/"United Kingdom" is accepted for GB) as a single value, a repeated parameter or a CSV.
regionScopes is a JSON array of OR-ed branches {region, channels, brandId?,
campaignId?, phoneNumber?} with channels from tenDLC, virtualLongCode, tollFree,
shortCode and p2p; [] matches nothing and omitting both keeps the existing scope.
Example:
[{"region":"US","channels":["tenDLC"],"brandId":["BUS1"]},
 {"region":"GB","channels":["virtualLongCode"],"phoneNumber":["447400123456"]}]
GET /message always accepts them, as do the analytics and DNC reads.

getAnalytics, getAnalyticsDetail, getAnalyticsThroughput and getDncAnalytics
accept registrationId (a single id or an array, sent as repeated registrationId
parameters like campaignId): filter to traffic attributed to these registrations. Except on
getAnalyticsThroughput, which has no phoneNumber filter, a phoneNumber filter
takes precedence. getPhoneNumbers accepts a single registrationId to list the
numbers provisioned under that registration.

getAnalyticsBySubgroup, getAnalyticsByErrorCode and getDncRecords accept registrationId
the same way, with the same precedence. getMessages accepts
registrationId: it filters to messages attributed to those
registrations, and a phoneNumber filter narrows further. Every method returns 400 when
registrationId is combined with campaignId.

getAnalyticsFilterOptions returns each phone number with its type (TOLL_FREE,
SHORT_CODE, ALPHANUMERIC, VIRTUAL_LONG_NUMBER, and older local-number spellings) and
country (ISO-2), null when unknown. TOLL_FREE, SHORT_CODE and ALPHANUMERIC are channels
by type; a US number of any other type is 10DLC and a non-US one is a Virtual Long Code.
It also returns carriers, a plain array of carrier name strings.

UK sending is SMS only, from a +44 virtual long code to GB mobile recipients; MMS
and group MMS are unavailable. POST /message/estimate accepts a +44 sender
(recipients 10-15 digits) and returns region "GB", or "CA" for a Canadian sender.
A READY alphanumeric sender ID (e.g. "ACME") also sends SMS to UK recipients only;
its estimate includes the opt-out footer.

TEMPLATES
--------------------------------------------------------------------------------
Versioned, raw message templates. One namespace, templates, on /template.
The channel is read from the body on create; list takes an optional channel
filter and capabilities an optional channel. Every call answers 404 while the
environment's RCS switch is off. Every call carries groupId: GET in the query string, JSON
writes in the body, the media upload as a form field.

A template has a head {templateId, groupId, channel, name, tag,
archivedAt, draftVersion, publishedVersion, revision,
createdBy, createdAt, updatedAt} and numbered versions
{version, state (DRAFT|PUBLISHED), body, contentHash, publishedAt, ...}. Reads
of one template return {head, version}; lists return {data, total, page, limit}.
The create and update responses add validation ({valid, errors, warnings}, null when the checks could not run), and publish adds warnings. A draft saves even when validation lists errors. On an RCS send, a blocked row carries blockReason, reason and issues.

with summaries that add state and hasUnpublishedChanges.

create creates draft version 1 from name (1-120 chars, unique per
group and channel), body and optional tag (201). get takes version: a
number, "draft" or "published"; omitted reads the published version, else the
draft, and an explicit selector never falls back (404). update saves the
draft from name / tag / body; writes apply directly (last write wins). Leave the
tag key out to keep it; set it to null to clear it. A write to an archived
template answers 409 {code:"TEMPLATE_ARCHIVED"} and a name already used in the
group and channel 409 {code:"TEMPLATE_NAME_TAKEN"}. publish takes only
groupId and always publishes the current draft; it answers 400
{code:"TEMPLATE_INVALID", errors, warnings} for an incomplete draft, 409
{code:"NO_DRAFT"} when there is none and 409 {code:"DRAFT_CHANGED"} when the
draft changed while it was being published (publish again). archive takes only
groupId.
validate checks exactly one of body or version and never writes. capabilities returns the
server's block kinds, action types, limits, media rules, time to live ranges,
traffic types per use case and iPhone layout numbers, and with provider
(infobip|sinch) that provider's limits and unsupported features.
uploadMedia sends multipart fields file and groupId and returns
{mediaId, url, bytes, mimeType, kind, width, height, ...} (201).

The body is the raw RcsTemplateBody {channel:"rcs", contentFormat?, content,
variables, defaults, fallback}; the SDK sends it unchanged and offers no
conversion, duplication or starter helpers. contentFormat defaults to
"content.v1" (content:{blocks}, the only format the API stores and returns);
"google.rcs" sends Google's RBM AgentContentMessage as content, which the API
converts to content.v1. A VIEW_LOCATION suggestion takes latitude/longitude or
an address the API geocodes; geocodeAddress(['groupId', 'address']) resolves
one for an author (400 LOCATION_NOT_FOUND, 429 past the group's lookup window,
503 when the server has no geocoding provider). Unknown keys are rejected.
Placeholders are {{key}}; {{sender_name}} is reserved. Writes accept an
idempotency key. Reads (including validate and capabilities) need
admin, developer, api, billing or user; writes need admin, developer or api.

LANGUAGE EXAMPLE
  $body = [
      'channel' => 'rcs',
      'content' => ['blocks' => [['id' => 'b1', 'kind' => 'text', 'text' => 'Hi {{first_name}}']]],
      'variables' => [['key' => 'first_name', 'type' => 'text', 'required' => true]],
  ];
  $created = $signalHouse->templates->create(['groupId' => 'G1', 'name' => 'Welcome', 'body' => $body],
      ['idempotencyKey' => $uuid]);
  $head = $created['data']['head'];
  $signalHouse->templates->update($head['templateId'], [
      'groupId' => 'G1',
      'tag' => null,   // null clears the tag; leave the key out to keep it
  ]);
  $signalHouse->templates->validate($head['templateId'], ['groupId' => 'G1', 'version' => 'draft']);
  $signalHouse->templates->publish($head['templateId'], ['groupId' => 'G1']);
  $signalHouse->templates->list(['groupId' => 'G1', 'channel' => 'rcs', 'state' => 'PUBLISHED']);
  $signalHouse->templates->capabilities(['groupId' => 'G1', 'provider' => 'infobip']);
  $signalHouse->templates->geocodeAddress(['groupId' => 'G1', 'address' => '88 Lakeshore Drive, Chicago']);
  $signalHouse->templates->uploadMedia(['groupId' => 'G1', 'file' => 'hero.png', 'fileName' => 'hero.png']);


RCS AGENTS  ($signalHouse->rcs->agents)
--------------------------------------------------------------------------------
RCS agents under /rcs/agent. An agent links one brand and one campaign, of
any registration type: the campaign's numbers are its SMS fallback, and the
brand and campaign supply the company identity and consent text for the
carrier launch. One brand or campaign can serve many agents. An agent is a
registration (type RCS_AGENT, agentId = registrationId "RCSA" + 10
characters), so the registrations methods read and edit the same record. 404
while RCS is disabled for the environment; 400 while the group's rcsEnabled
flag is off. To use a new brand and campaign, create the brand
(brands->createBrand), wait until it is VERIFIED, create the campaign
(campaigns->createCampaign), then link them.

The agent: {agentId, groupId, subgroupId, status, registrationStatus, stage,
brandId, brandRef, campaignId, campaignRef, links, agent, consent, useCase,
billingCategory, defaultFallback, excludedCarriers, testers, contact,
testerInvites, carriers, launchable, review, submittedAt, approvedAt, history,
createdAt,
updatedAt}. launchable is true
  when the launch request would be accepted now. brandRef and campaignRef are the
linked records' _ids; brandId and campaignId are their current public ids
(brandId is null until TCR assigns one). links = {brand: {state: OK |
NOT_VERIFIED | MISSING, ...}, campaign: {state: OK | NOT_ACTIVE | MISSING |
NONE, ...}}; a deleted brand or campaign reads MISSING. status: DRAFT,
PENDING_REVIEW, REJECTED, AGENT_CREATING (approved, waiting for the carrier
launch), ARCHIVED.

Body fields: agent (name, description, color, logoUrl, heroUrl, phone,
website, email, phoneLabel, websiteLabel, emailLabel (captions, max 40;
submit defaults them to Call, Website and Email), privacyPolicyUrl, termsUrl),
consent (optInDetails, optInUrl, optInResponse, optOutDetails, optOutResponse,
helpResponse, campaignDescription, messageExamples, estimatedMonthlyVolume,
launchVideoUrl; every field is required before submit), useCase (OTP |
TRANSACTIONAL | PROMOTIONAL | MULTI_USE), billingCategory (NON_CONVERSATIONAL
default | CONVERSATIONAL), defaultFallback {mode, channel, from},
excludedCarriers ([] or ['T_MOBILE'], the carrier partner's carrier name) and
testers (up to 200 numbers).
Only these keys and brandId / campaignId are sent.

  create(array $params, array $options = [])
    POST /rcs/agent. Create a draft (201). brandId is a carrier brand ID,
    provisional UUID or _id; campaignId (optional until submit) is a campaign
    ID or _id of that brand. The agent's subgroup is the brand's. Blank
    consent fields fill from the campaign. Unset or null keys are omitted.
    Required: brandId

  list(array $params = [], array $options = [])
    GET /rcs/agent with groupId, subgroupId, status (one value or an array,
    sent as repeated keys), brandId, campaignId, page, limit. Newest first.
    brandId / campaignId return the agents linked to that brand or campaign.
    Returns {data, total, page, limit}.

  get(string $agentId, array $options = [])
    GET /rcs/agent/:agentId. One agent with the live state of its links.

  update(string $agentId, array $params, array $options = [])
    PUT /rcs/agent/:agentId with brandId?, campaignId?, agent?, consent?,
    contact?, useCase?, billingCategory?, defaultFallback?, excludedCarriers?,
    testers?.
    Edit a DRAFT or REJECTED agent. agent and consent merge field by field;
    other keys replace. A key set to null is sent as null ('campaignId' =>
    null unlinks); leave a key out to keep it. 409 once submitted.

  validate(string $agentId, array $options = [])
    POST /rcs/agent/:agentId/validate. Returns {valid, errors, warnings} of
    {field, reason}; writes nothing.

  submit(string $agentId, array $options = [])
    POST /rcs/agent/:agentId/submit. Create the agent at the carrier partner,
    with no review first. Needs the full profile, useCase and
    NON_CONVERSATIONAL billing; otherwise 400 with details {code:
    "REGISTRATION_INCOMPLETE", errors, warnings}. The agent moves to
    AGENT_CREATING, then IN_TESTING once the partner reports it ready.

  launch(string $agentId, array $options = [])
    POST /registration/:agentId/launch. Request the launch: the launch
    requirements are checked (a VERIFIED brand, the campaign, the full consent
    with the launch video, the contact) and the agent goes to PENDING_REVIEW;
    Signal House's approval files the launch with the carrier partner. Allowed
    from IN_TESTING, REJECTED and CARRIER_REJECTED (409 otherwise); a failed
    requirement is 400 REGISTRATION_INCOMPLETE.
    The request charges the agent's launch fees: a wallet that cannot cover
    them gets a 402, and the agent stays where it is.
    The agent's launchFees quotes what the next request charges.

  archive(string $agentId, array $options = [])
    POST /rcs/agent/:agentId/archive. Archive the agent.

  resendTesterInvite(string $agentId, string $phoneNumber, array $options = [])
    POST /rcs/agent/:agentId/testers/:phoneNumber/resend. Resend a tester's expired invitation.

  uploadAsset(string $agentId, array $params, array $options = [])
    POST /rcs/agent/:agentId/asset, multipart fields kind and file. $params:
    kind (logo | hero), file (a path or an open stream), fileName?. Host a
    logo (224 x 224 px, 50 KB max) or hero (1440 x 448 px, 200 KB max) PNG or
    JPEG and set it on the draft. Required: agentId, kind, file

Pass ['idempotencyKey' => $uuid] as $options on create, update, submit,
archive and uploadAsset to make a retry safe (see IDEMPOTENT REQUESTS).

  $created = $signalHouse->rcs->agents->create([

RCS MESSAGES  ($signalHouse->rcs->messages)
--------------------------------------------------------------------------------
  Send through an agent. 404 while RCS is off for the environment, 403 while
  the group's rcsEnabled flag is off, 409 while the agent cannot send yet.

  send(array $params, array $options = [])
    POST /message/rcs.
    Send to up to 100 recipients. A blocked recipient gets a BLOCKED message and
    the rest still send. Exactly one of templateId or content; at most one of
    ttlSeconds or expireTime. contentFormat: content.v1 (default) | google.rcs.
    recipients is a list of { phoneNumber, variables, clientMessageId, metadata }.
    fallback is { mode (auto, rcs_only, sms_only), channel (auto, sms, mms), from,
    content: { text, mediaUrls }, validitySeconds }; without content the
    template's fallback, else a generated one, is used. simulate: not_capable |
    ttl_expired | delivered | read, approved testers only.
    Required: agentId, recipients
    Returns: { requested, enqueued, failed, bulkId, messages } (201)

  validate(array $params, array $options = [])
    POST /message/rcs/validate. Check a send; writes nothing. Takes the same
    arguments as send. Required: agentId, recipients
    Returns: { valid, errors, warnings, billingClass, segments,
    estimatedCostMicros, unsupportedFiles, recipients }. It runs a send's
    checks and holds no funds. valid is true only with no errors.

  estimate(array $params, array $options = [])
    POST /message/estimate with channel "rcs" added. Price a draft in
    microdollars; no charge or send. Exactly one of recipients or
    recipientCount. The fallback's from is optional for an estimate; with
    none, the fallback leg is priced on the channel of the agent's linked
    campaign. Required: agentId
    Returns: { billingClass, segments, recipientCount, rcsLeg, fallbackLeg,
    totals, balance, issues, warnings }
    rcsLeg.mediaSurcharge is the carrier's surcharge on media over 5 MB,
    already inside rcsLeg.cost; a message over 100 MB adds a MEDIA_TOO_LARGE
    issue.

  capabilities(string $agentId, array $phoneNumbers, array $options = [])
    POST /rcs/capabilities. Report which numbers (up to 500) can receive RCS.
    Required: agentId, phoneNumbers
    Returns: { results: [{ phoneNumber, capability }] }, capability being
    ENABLED, UNREACHABLE or UNKNOWN

  get(string $messageId, array $options = [])
    GET /message/:messageId. Get one message; the same route as
    $signalHouse->messages->getMessage. Required: messageId

  list(array $params, array $options = [])
    GET /message with messageType=RCS. $params: groupId, from (sent as
    startDate), to (sent as endDate), agentId? (sent as registrationId),
    status?, page?, limit?, templateId?, templateVersion?, bulkId?,
    fallbackReason?, billingClass?, deliveredChannel?, isTest?.
    Required: groupId, from, to

  Pass ['idempotencyKey' => $uuid] as $options on send to make a retry safe (see
  IDEMPOTENT REQUESTS).
